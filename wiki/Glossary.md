# Glossary

Terms used across this wiki, in alphabetical order. Where relevant, entries
note how the term is used specifically in ClaudeCode Remote, not just its
general meaning.

| Term | Meaning |
|---|---|
| **Agent lock** | A lock file (`/run/claudecode-locks/agent-<pid>`) created automatically whenever a coding agent runs, via a shell wrapper. Planned to expire automatically after 6 hours of staleness so a crashed agent can't block updates forever — unlike a terminal lock, which never expires. See [Idle Update System](Idle-Update-System). |
| **Alternate screen buffer** | A second terminal screen that full-screen programs (vim, htop, Claude Code's Ink-based UI) switch into so their drawing doesn't scroll into the normal scrollback. Entered/exited via the escape sequences `?1049h`/`?1049l`. The client-side terminal emulator must handle this correctly for full-screen TUIs to render and restore cleanly. |
| **Argon2id** | The password-hashing algorithm planned for the owner login portal, chosen over bcrypt for its stronger resistance to GPU-assisted cracking attempts. Used only for the rare pairing/step-up flow, never for everyday terminal access. |
| **CGNAT** | Carrier-Grade NAT — an ISP-level NAT layer that means the IP address visible on your router isn't actually publicly routable, so classic port forwarding doesn't work. Common on German mobile and some cable connections; the reason this project needs CloudGate instead of a simple port-forward. |
| **CloudGate** | A separate, MIT-licensed self-hosted project (also by this project's author) that orchestrates Cloudflare Tunnel via a Web UI. Not a relay server itself — it automates tunnel/DNS/ingress setup so a local service becomes reachable at `subdomain.your-domain.com` without opening any port. |
| **Cloudflare Tunnel** | An outbound-only connection (`cloudflared`) from the server to Cloudflare's edge network, which then proxies public HTTPS traffic back to it. Solves CGNAT without port forwarding; TLS termination happens at Cloudflare's edge, so the daemon itself never needs to manage certificates. |
| **Ed25519** | The elliptic-curve algorithm used for two distinct keys in this project: the SSH key pairs securing server access (one per device, individually revocable) and the per-device key used for everyday terminal-daemon authentication after pairing. |
| **FIDO2** | The standard behind hardware security keys (e.g. YubiKey) acting as roaming WebAuthn authenticators. Planned as the passkey fallback for Linux Desktop, which has no mature native platform passkey API as of this writing. |
| **Idle update** | The autonomous system update that runs only when no agent lock or terminal lock is active. Runs on a systemd timer roughly every 30 minutes; skips entirely if any lock file exists. See [Idle Update System](Idle-Update-System). |
| **Passkey** | A WebAuthn credential bound to a specific origin domain, combining possession of a device with local biometric/PIN unlock. Planned as one of three factors required for device pairing, and alone for step-up prompts on sensitive actions. |
| **PTY** | Pseudo-terminal — the OS-level construct that lets a program behave as if it's connected to a real terminal. The daemon attaches to tmux through its own PTY (via Go's `creack/pty`) and forwards raw bytes; it never parses what flows through it. |
| **Relying party (RP ID)** | The domain a WebAuthn passkey is cryptographically bound to. Must be a fixed domain, not an IP — this project's open decision D-04 is exactly this domain, and changing it after passkey rollout invalidates every registered passkey. See [Roadmap and Decisions](Roadmap-and-Decisions). |
| **restic** | The backup tool planned for automatic snapshots of the daemon's database, agent configs, the exchange folder, and untracked project files. Deduplicating and client-side encrypted, even though backups are stored locally to start with. |
| **Sacred paths** | Files and directories an updater must never overwrite or delete — encryption keys, user databases (including SQLite `-wal`/`-shm` siblings), user config overrides, TLS certificates. Documented per project; see the repo's own conventions in `CLAUDE.md`. |
| **SMB3** | The file-sharing protocol version planned for the `backups` and `exchange` Samba shares, chosen over NFS for native transport encryption. Bound exclusively to the Tailscale interface — never exposed publicly or through CloudGate. |
| **Step-up auth** | A renewed passkey prompt required for sensitive individual actions (revoking a device, pairing a new one, deleting a backup) even from an already-paired device. Sits between the lightweight daily Ed25519 auth and the full three-factor pairing flow. |
| **Tailnet** | The private mesh network formed by devices running Tailscale together — in this project, the server and every authorized client device. |
| **Tailscale** | The WireGuard-based mesh VPN chosen (decision D-01) for direct device-to-server connections: automatic NAT traversal, per-device ACLs, and no public endpoint to secure. Used for the server's own devices; CloudGate covers the web client and unenrolled devices instead. |
| **Terminal lock** | A lock file (`/run/claudecode-locks/terminal-<session-id>`) created as soon as a terminal session exists in the daemon. Deliberately persists indefinitely — it is only removed when the user explicitly closes the terminal, never by staleness cleanup like an agent lock. |
| **TOTP** | Time-based One-Time Password (RFC 6238) — the second of three planned pairing factors, verified against a secret stored encrypted server-side, compatible with any standard authenticator app. |
| **tmux** | The terminal multiplexer this project uses as its actual persistence layer. The daemon attaches to and detaches from tmux sessions rather than reimplementing session survival itself; `set -g window-size latest` is planned so a session tracks whichever device last sent input instead of shrinking to the smallest attached window. |
| **tus** | An open, standardized protocol (tus.io) for chunked, resumable file uploads, planned as the transport for the file API so an interrupted upload doesn't require restarting from zero. |
| **WebAuthn** | The W3C standard underlying passkey authentication, binding credentials to a relying party domain. Server-side implementation planned via `go-webauthn/webauthn`. |
| **WireGuard** | The modern VPN protocol Tailscale is built on; provides the encryption layer for the private mesh without this project needing to implement its own transport crypto. |
| **xterm.dart / xterm.js** | The terminal emulator libraries planned for the client apps (`xterm.dart` in Flutter, `xterm.js` for a web test client). They do the actual VT100/256-color/Unicode rendering the daemon deliberately doesn't do server-side. |
